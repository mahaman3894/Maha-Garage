마하개러지 수정본 1.0.3 (versionCode 4)
수정일: 2026-10-20

이 문서가 이번 수정본의 변경 내역입니다. 기존 HISTORY_FIX_1_0_1_KO.txt 등은 과거 기록입니다.

수정 내용
1. Google Play에서 확인한 필수 업데이트 대상 버전을 로컬에 저장합니다.
   화면 재생성이나 앱 재실행 후 조회가 실패해도 이미 확인된 필수 차단을 유지합니다.
   설치 버전이 대상 이상이면 차단을 해제합니다.
2. 업데이트 제공 여부, 즉시 업데이트 실행 가능 여부, 진행 중, 상태 미확인을 구분합니다.
   즉시 업데이트가 불가능한 필수 대상은 스토어 안내 화면을 유지합니다.
   업데이트가 명시적으로 없다고 정상 확인되면 배포 철회 상황을 허용하도록 저장된 요구를 해제합니다.
   필수 상태가 확인된 적 없는 오프라인 실행은 로컬 차량 정보를 사용할 수 있습니다.
3. 시작 API false 반환, 예외, 취소를 안내하고 재시도합니다.
   중복 조회/실행을 억제하고, 이전 화면의 늦은 응답을 무시하며 조회는 15초 후 종료합니다.
   스토어 복귀와 진행 중 업데이트 복원은 같은 조회 경로를 사용합니다.
   차량 알림의 이동 대상도 화면 재생성 동안 보존합니다.
4. 보험 날짜가 삭제됐거나 잘못됐거나 갱신되어 알림 대상에서 벗어나면 기존 보험 알림을 취소합니다.
5. 검사/보험 알림을 끄면 해당 종류의 기존 알림만 즉시 취소합니다.
   설정 저장·취소와 실제 발송을 같은 잠금으로 묶어 OFF 이후 이전 작업이 알림을 다시 올리지 못하게 했습니다.
6. 실제 발송 직전에 앱 설정, OS 알림 권한, 채널 및 채널 그룹 차단을 확인합니다.
   차단되어 발송하지 못한 알림은 성공으로 처리하거나 쿨다운을 갱신하지 않습니다.
7. 앱 내 버전 표시는 설치된 패키지 버전을 읽도록 변경했습니다.
8. Play 업데이트 라이브러리가 가져오던 구형 Fragment를 1.8.9로 명시해 ActivityResult API의 호환성 Lint 오류를 해결했습니다.
   공식 변경 내역: https://developer.android.com/jetpack/androidx/releases/fragment#1.8.9

보존 사항
- Room DB 버전은 9입니다. 스키마, 엔티티, 기존 마이그레이션은 변경하지 않았습니다.
- Firebase 구성 파일 2개는 원본과 동일합니다. 서버 규칙은 변경하지 않았습니다.
- 검사/보험 중심의 알림 정책과 원본 디자인을 유지했습니다.
- 원본의 receipts/restored_photos 시스템 백업 설정은 유지했습니다.

테스트
- 기존 90개 + 새 정책 회귀 테스트 14개, 총 104개 단위 테스트를 포함합니다.
- 새 UpdateRequirementPersistenceTest에는 실제 SharedPreferences에 저장한 대상이 재생성 후 유지되는지,
  업데이트된 설치에서 해제되는지 확인하는 기기 테스트 2개를 추가했습니다.
- 실제 실행 결과는 압축파일의 검증결과.txt를 확인하십시오. 테스트를 포함한 것과 실행한 것은 구분합니다.

빌드/설치
1. Android Studio에서 MahaGarage 폴더를 열고 로컬 SDK 경로와 JDK 17을 설정합니다.
2. Gradle wrapper로 assembleDebug, testDebugUnitTest, lintDebug를 실행합니다.
3. 설치된 앱을 삭제하지 말고 같은 서명의 APK로 업데이트하십시오. 데이터를 지우거나 앱을 제거하면 안 됩니다.
4. Play 배포 전에 versionCode 4가 아직 사용되지 않았는지 확인하고, 사용 중이면 더 큰 코드로 빌드합니다.

이 PC에서 확인한 Windows Java 빌드 환경 문제
- 한글 임시 디렉터리에서 Java 내부 Unix domain socket 연결이 Invalid argument: connect로 실패했습니다.
- 이번 검증 프로세스에만 JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/Windows/Temp를 지정해 우회했습니다.
- 앱 코드나 프로젝트의 공통 설정에 이 PC 전용 경로를 넣지 않았습니다.
- Gradle 테스트 실행기의 UTF-8 인자 파일과 Windows CP949 해석이 달라 GradleWorkerMain을 못 찾는 문제도 있었습니다.
  이 PC에서만 Gradle 시작 인자를 -Dorg.gradle.jvmargs="-Xmx2048m -Dfile.encoding=MS949" -Dfile.encoding=MS949로
  지정해 해결했습니다. 테스트 JVM 자체의 UTF-8 설정은 기존대로 유지합니다.
  다른 운영체제나 UTF-8 Windows 환경에는 이 인코딩 우회를 일괄 적용하지 마십시오.

배포 전 기기 확인
- 필수 업데이트 취소 → 오프라인 → 화면 회전/프로세스 종료 후 재실행.
- Play 즉시 업데이트 불가, 스토어 이동/복귀, 다운로드 중 복귀.
- 보험 만료일 삭제 후 점검, 알림 OFF 시 기존 알림 취소, OS 채널 OFF→ON 후 재점검.
- 기존 앱 위에 업데이트 설치한 뒤 차량·정비·타이어·사진 데이터 보존.
- 시스템 백업/복원 후 사진 열기. Google Auto Backup의 용량 한도는 별도로 적용됩니다.

압축에서 제외한 파일
- 기존 build/.gradle/.kotlin 캐시, 이전 APK, local.properties 등 PC별 설정.
- 과거 PC의 절대 경로에 의존하는 java_test_args.txt와 run_tests.py.
- Java 실행환경과 임시 검증 도구는 배포 프로젝트에 포함하지 않습니다.
