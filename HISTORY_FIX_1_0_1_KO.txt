MAHA Garage v9 수정본 / 앱 버전 1.0.1
원본: MahaGarage_v9_updated.zip

실제 코드 수정 내용
1. 패드 마커의 전륜/후륜을 기록 대상에 그대로 반영합니다. 통합 카드도 기본 전륜으로 열고 양쪽은 사용자가 선택합니다.
   위치를 바꾸면 해당 위치의 주기와 관리 기준을 다시 불러옵니다.
   양쪽 값이 다르면 공란/안내로 표시하며, 수정한 값만 공통 적용합니다. 양쪽 설정은 하나의 DB 트랜잭션으로 저장합니다.
2. 빠른 소모품 정비 모달의 날짜/거리/비용/두께 입력을 검사합니다.
   잘못된 숫자를 임의의 현재 거리나 0원으로 바꾸지 않습니다. 비용 미입력은 추가 비용을 만들지 않습니다.
   저장 중 중복 클릭/닫기를 막고, 성공 후 닫으며, 저장 오류는 모달에 표시합니다.
   엔진오일/필터 및 양쪽 패드 비용 분배에서 홀수 원 합계도 보존합니다. 패드 두께 기본 9mm도 빈칸으로 변경했습니다.
3. 거리·기간 주기는 각각 비워서 해제할 수 있습니다. 최소 하나의 거리/기간/기존 시간 주기가 있으면 됩니다.
   관리 시작 날짜/거리도 선택 입력입니다. 미수정 시간 주기/기준과 실제 교환 이력 캐시는 보존합니다.
4. 같은 4mm 측정값이 관리 기준 등록 후 정상으로 바뀌지 않습니다.
   3mm 이하 경고 및 이미 도달한 정기 점검 상태도 유지합니다. 측정만 있는 항목의 주기 게이지를 만들지 않습니다.
5. 백업은 타이어 setId/assignedWheelPosition을 포함하고 구버전의 누락 필드도 읽습니다.
   차량 사진·영수증·검사증 파일을 JSON에 포함하여 다른 폰에서 새 내부 경로로 복원합니다.
   같은 사진은 중복 저장하지 않고, 복원 DB 저장 실패 시 새로 만든 사진을 정리합니다.
   이미 원본 파일이 사라진 사진은 복원할 수 없으며 누락 개수를 표시합니다.
6. 휴대폰 이전을 GZIP 압축/분할 문서 전송으로 변경했습니다. 문서당 데이터는 최대 160,000자입니다.
   번호를 트랜잭션으로 예약하여 충돌 덮어쓰기를 막고, 복원 잠금/사용 완료 처리 및 SHA-256 검증을 추가했습니다.
   실패 시 복원 잠금을 해제합니다. 정상 복원 후 조각을 삭제합니다.
   기존 단일 payload 전송은 새 앱에서 읽습니다. 새 전송을 받는 폰도 이번 버전이어야 합니다.
7. 저장 시 전체 차량 방문 목록을 읽던 중복 확인을 ID 조회로 바꾸고, 변경한 품목의 이력만 재계산합니다.
   카 히스토리는 DB에서 선택한 차량/기간만 조회합니다. 정비 이력은 화면이 구독할 때만 조회하고 미사용 캐시를 해제합니다.
8. 앱 versionCode=2, versionName=1.0.1로 변경했습니다. Room DB 버전은 9를 유지합니다.

데이터 및 구성 보존
- MahaGarageDatabase.kt, Room schema JSON 및 기존 엔티티는 원본과 동일합니다. 새 마이그레이션/초기화/테이블 삭제를 추가하지 않았습니다.
- Firebase 구성 파일 2개는 원본과 바이트 단위로 동일합니다. 실제 서버 설정/보안 규칙을 배포하지 않았습니다.
- 차량 탑뷰/연결선 레이아웃 파일과 차량 이미지 등은 유지했습니다.
- 기존 앱 삭제 없이 같은 서명으로 업데이트해야 설치된 앱의 데이터를 유지할 수 있습니다.

검증 결과
- 최종 main/debug Kotlin 소스 전체: Compose 컴파일러 포함 직접 컴파일 통과. JVM 타깃 17.
  기존 의존성/R.jar 및 Kotlin 2.0.21 컴파일러를 사용한 소스 검사이며 Gradle/KSP/APK 빌드와는 별개입니다.
- 최종 단위 테스트: 80개 실행, 80개 통과. 기존 60개 + 실제 운영 정책/코덱을 호출하는 신규 20개입니다.
  후륜 대상 선택, 기준 개별 해제, 기록/시간 보존, 오류 입력 거부, 4mm 경고, 타이어 전체 필드 왕복,
  수 MB 데이터 분할/압축/복원 및 체크섬 거부 등을 포함합니다.
- 새 DAO SQL은 SQLite에서 실제 문장으로 기간 필터/차량 구분/품목 필터/ID 존재 여부를 검사해 통과했습니다.
- DB 코드/schema9가 원본과 동일함을 확인했습니다. 이전 검토에서 v3~v8→v9 SQLite 시뮬레이션도 통과한 구조입니다.
- 기기 테스트 3개를 추가했습니다: 양쪽 설정 원자성, 후륜 교환 시 전륜 보존, 실제 Room+사진+타이어 백업 왕복.
  기존 기기 마이그레이션 테스트도 현재 DB 9까지 전체 마이그레이션을 등록하도록 수정했습니다.
  이 기기 테스트들은 이번 환경에서 실행하지 못했습니다.
- Gradle assembleDebug/testDebugUnitTest 실행을 시도했지만, 환경의 native-platform.dll 및 loopback 연결 오류로
  빌드 시작 단계에서 막혔습니다. APK는 생성/설치하지 않았고, KSP 생성 DAO 및 실제 Room 실행은 미검증입니다.
- 실제 폰 화면, Firebase 서버 송수신/규칙, 알림, PDF 렌더링/인쇄 및 전체 앱의 장시간/대용량 실측은 미검증입니다.
  이번 수정은 점검도 디자인 변경을 포함하지 않으며 시각적 실행 완료를 주장하지 않습니다.

Firebase 전송 운영 확인
- FIREBASE_TRANSFER_NOTES.md에 새 문서 구조와 권한/TTL 확인 사항을 적었습니다.
- 기존 서버 규칙이 문서 이름/필드를 제한한다면 분할 문서와 트랜잭션을 허용하는지 실제 프로젝트에서 확인해야 합니다.
- 48시간 만료는 앱에서 사용을 거부합니다. 서버 자동 삭제는 expiresAtTimestamp TTL 설정이 있어야 동작합니다.
- 원본 JSON 최대 160MiB, 압축 전송 최대 64MiB, 사진 개당 12MiB/합계 96MiB로 제한합니다.
  무제한 메모리/전송, 중단 지점 재개, 서버 인증/요청 제한의 배포는 이번 수정에 포함되지 않습니다.
- 전체 기간을 직접 선택하거나 전체 정비 목록을 열면 해당 결과 전체를 읽습니다. 완전한 페이지 조회 전환은 하지 않았습니다.

사용 방법
1. ZIP을 새 폴더에 풀고 안의 MahaGarage 폴더를 Android Studio에서 엽니다.
2. 본인 SDK/Gradle JDK 설정으로 Sync 후 빌드합니다. local.properties 및 build/.gradle은 ZIP에서 제외했습니다.
3. 설치된 앱을 삭제하지 말고 기존과 같은 서명으로 업데이트합니다.
4. 실제 폰에서 패드 기록 대상, 설정 저장/실패, 백업 왕복을 먼저 확인합니다.
   다른 폰 이전은 두 폰 모두 이번 버전으로 업데이트한 뒤 확인합니다.
