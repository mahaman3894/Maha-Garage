# MahaGarage 1.1.3

## 1.1.3 변경

- 튜토리얼 5페이지 ‘차량번호 조회안내’에 다음 안내를 통합했습니다.
  - 차량번호 조회 버튼에서 서비스 제공 상태를 확인할 수 있습니다.
  - -해당 서비스는 준비중입니다-
  - 개인정보 수집관련 이슈
- 기존 6·7페이지를 삭제했습니다. 5페이지는 안내만 표시하며 중복 팝업 시연은 열지 않습니다. 실제 차량 등록의 차량번호조회 버튼은 종전처럼 준비 중 팝업을 표시합니다.
- 기존 9페이지 제목을 ‘차량 카드를 선택해 소모품 변경 사항을 등록하세요.’로 변경했습니다.
- 삭제에 따라 전체 20페이지입니다. 기존 9페이지는 새 7페이지, 기존 12·13페이지는 새 10·11페이지가 됩니다.
- 운용 차량 2대 이상: Rest Area도 운용 카드와 같은 열 수·너비를 사용합니다. 휴면 차량이 1대여도 와이드로 늘리지 않습니다. 두 카드 모두 내부 여백 14dp, 이미지 비율 2:1이므로 이미지 영역 크기도 같습니다.
- 운용 차량 1대: 운용 카드는 전체 너비를 유지하고, 휴면 차량은 자체 개수와 화면 폭에 따라 1~4열로 나눕니다. 운용 차량이 없을 때도 휴면 차량 자체 개수로 배치합니다.

## 유지 동작

다음 버튼 #87CEFA, 안내 카드 기본 위치 고정과 겹칠 때만 이동, 화면/안내 카드 탭으로 다음 진행, 강조 영역 원래 밝기 유지, 정비 입력창 강조를 유지했습니다. 최초 실행 여부는 로컬에 저장하고 설정에서 다시 볼 수 있습니다.

실제 화면과 ViewModel/Repository를 사용하되 연습은 별도 메모리 전용 Room DB에서 진행합니다. 실제 차량·정비·주유 기록과 DB 스키마는 변경하지 않습니다. 이전 단계·화면 재생성 시 바뀐 단계 순서에 맞게 연습 데이터를 복원합니다. 주유 예시는 50,000 → 50,600km, 50L 가득 주유로 12.00km/L입니다. 카메라와 전화는 실제 외부 기능을 실행하지 않는 연습 화면입니다.

## 빌드 및 검증

- Android SDK 36 / 프로젝트 Gradle Wrapper
- 앱: `gradlew.bat :app:assembleDebug` 또는 `:app:assembleRelease`
- 단위 테스트: `gradlew.bat :app:testDebugUnitTest`
- 기기 테스트: `gradlew.bat :app:connectedDebugAndroidTest`
- 차고 배치 테스트는 운용 2대+휴면 1대, 운용 1대+여러 휴면 차량, 화면 폭별 2~4열 조건을 포함합니다.

전달 소스에는 개인 SDK 경로, 서명 키·비밀번호와 빌드 캐시가 없습니다. 정식 서명 빌드에는 원본 키와 `RELEASE_STORE_FILE`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`를 로컬 속성 또는 환경 변수로 제공하세요.

## 기존 폴더에 합치기

기존 프로젝트를 백업한 후 압축 안의 MahaGarage 폴더 **내용**을 기존 MahaGarage 프로젝트 루트에 덮어쓰세요. app 폴더끼리 합쳐지는 위치입니다. MahaGarage/MahaGarage로 중첩하지 마세요. 기존 local.properties와 keystore는 유지합니다. Android Studio에서 동기화 후 빌드하세요.
